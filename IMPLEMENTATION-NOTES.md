# SmartWardrobe AI — Cobalt Editorial UI Refresh

## Included in this build

- Reworked the authenticated Today/overview page into a recommendations-first experience.
- Added featured outfit composition, two alternative looks, garment detail links, save, try-another, dismiss, Discover, recent garments, and saved-look status.
- Added empty-wardrobe, no-compatible-combinations, loading, request-error, and image-fallback states.
- Applied the agreed cobalt / vermilion / butter / cool-paper / ink palette across the existing UI token system.
- Updated navigation labels to Today and Discover.
- Preserved the existing routes, authentication flow, wardrobe repository, garment CRUD and upload components, and existing Discover/Saved/My Style/Settings pages.

## Important implementation notes

- Outfit suggestions currently use the existing deterministic, category-based `MockOutfitRepository` rules. They are not generated by a trained AI model.
- In HTTP mode, garment data comes from `HttpGarmentRepository`, while outfits and preferences are still backed by the existing mock repositories. This is unchanged architecture and should be integrated with the backend teammate's API contract later.
- The previously identified cross-account garment visibility bug is not fixed by this frontend UI refresh. Do not deploy with real users until backend account isolation is fixed and tested.

## Run locally

1. Extract this archive.
2. Open a terminal in the `smartwardrobe-ai` directory.
3. Run `npm install`.
4. Copy `.env.example` to `.env` and configure `VITE_API_BASE_URL` and `VITE_DATA_MODE` as appropriate.
5. Run `npm run dev`.
6. Run `npm run build` to verify the local toolchain.

This workspace could not complete a fresh dependency install because npm registry DNS/network access failed, so a production build could not be verified in this environment. No backend files are included or changed.

## Image consistency patch (October 2026)
- Today now uses labelled, branded garment placeholders while `VITE_DATA_MODE=mock` is active. This prevents unrelated stock photos from being presented as specific garments in recommendations and the recent archive.
- In HTTP mode, Today uses the image URL returned for each saved garment and falls back to a labelled placeholder if the URL is missing or fails to load.
- This is a display/data-integrity improvement, not a fix for the previously identified cross-account backend isolation issue.
- Build verification was not run in this environment because dependencies are not installed and package-registry access is unavailable. Run `npm install` and `npm run build` locally after extracting.


## Fast-track backend persistence update
- HTTP mode now persists saved outfits and My Style preferences in SQLite, scoped to the authenticated user.
- Outfit generation still uses the existing transparent category/occasion rule generator on the frontend; it is not a trained AI model.
- Existing localStorage mock data is not migrated to the backend. Saved outfits/preferences created in mock mode will not automatically appear in HTTP mode.
- This archive has not been run through npm build in this environment. Test login, save/unsave, preferences update, and account isolation locally before relying on it.

## Milestone 4 — Account isolation and saved-outfit integrity

- Saved outfit writes now validate that every referenced garment belongs to the authenticated account.
- Deleting a garment removes its reference from the same account's saved outfits; outfits with no remaining garments are removed.
- Added backend regression tests for cross-account garment reads, forged cross-account outfit references, saved-outfit/preferences isolation, and cleanup after garment deletion.
- Run tests from the project root with: `python -m pytest backend/tests -q`.
- These tests are useful regression coverage, not a complete production security audit. Set a strong `SMARTWARDROBE_SECRET`, configure HTTPS/secure cookies, and review deployment settings before public release.
